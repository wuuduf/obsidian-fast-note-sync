# 同步日志的失败重试

在同步日志中找到“可重试”的失败条目，点击“重试此页”。同一条目和同一分页同时只允许一个请求，按钮显示“等待完成”，状态显示“重试中”。收到分页元数据后仍会等待本地处理；只有原分页完成且没有新增本地失败才标记“已恢复”。已恢复条目移出“仅失败”视图，并清除该条未读失败标记。原错误原因与后续恢复说明均保留，文本日志也追加状态变化。

若重试再次失败，可处理原因后再次点击。服务端下载缓存 10 分钟未更新会过期，插件会明确显示“下载缓存已过期”，按钮改为“重新同步”。没有分页定位信息的旧记录也提供“重启同步”。点击后启动新的全量比对，不沿用可能已经推进的增量时间戳；原条目保持“重试中”，等新一轮真正完成再标记恢复。还有失败、未完成项或同步范围被关闭时不会显示已恢复。

首个分页回执等待上限为 30 秒，收到分页后处理等待上限为 5 分钟；超时会释放按钮并提供重新同步入口。断线、认证失败、取消、清空日志、会话变化或插件卸载也会释放在途状态。不会自动循环重试或自动覆盖正在进行的其他同步轮次；日志属于其他笔记库时需先切换笔记库。

四类资源（笔记、附件、配置、文件夹）共用此闭环。末页完成不依赖服务端额外 ACK；附件改名后需要重新下载时，原页等二进制文件落盘后才完成。异步操作保留来源 context，旧轮次的完成和失败计数不归入新轮次。

每轮同步都有独立的诊断 ID，分页重试和缓存过期后的全量重启继承原失败条目的 ID，路由隔离仍使用各自的 context。异步写盘失败保留来源轮次的 ID，不会误归到后来开始的新轮次。日志中显示完整 ID，可点击复制，也可在顶部输入完整或部分 ID 筛选；“仅看失败”与诊断 ID 筛选可以同时使用。

诊断 ID 同时通过 JSON 和 Protobuf 信封传递到服务端。合法格式为 1–64 个 ASCII 字符，首字符是字母或数字，其余允许字母、数字、`.`、`_`、`:` 和 `-`；它只用于定位问题，不是身份凭证。插件优先使用 Web Crypto UUID，旧运行时缺少 Crypto 时使用同格式的本地唯一性回退。

文本日志保存到插件私有目录中的 `sync.log`，包含 `[Trace: ...]` 和重试状态。单行限制 8192 字符，文件达到约 1 MiB 后轮换为新内容。清空和卸载会使旧写入队列失效；高频成功操作仍跳过磁盘写入。HTTP 诊断只记录方法、无查询参数的接口路径、状态与受控错误摘要，不记录凭据、请求正文或外部错误中的签名 URL。

单独运行 `npm test` 会跳过需要 Go 服务生成回执的互操作项；在生态根目录运行 `node scripts/validate-ecosystem-phase14.mjs` 会先生成真实回执，再运行完整插件测试及四项目回归。MediaForge 保持暂停。

浏览器验收夹具可用 `node scripts/serve-diagnostic-fixture.mjs` 启动，运行真实的日志 React 组件、日志管理器、中文词典与生成样式；Obsidian 宿主 API 与示例日志由夹具提供。桌面与移动截图位于 `output/playwright/diagnostic-desktop.png`、`diagnostic-mobile.png`。这验证 Chromium 中的界面和交互，不代表已经在 Obsidian 原生移动客户端测试。
